# 200개 채용공고 충족 수집 설계

## 목적

매일 전달하는 XLSX에 2년차 백엔드 개발자 기준을 만족하고 공개 상세 페이지로 확인한 **서로 다른 공고를 최대 200개** 담는다. 기존의 경력·직무·상세 확인 기준과 영구 조사 이력 기반 중복 제거는 유지한다.

## 수집 순서

1. 4일 주기의 기본 플랫폼군(사람인·잡코리아 3일, 원티드·랠릿 1일)을 각 플랫폼별 기존 상세 확인 한도까지 조사한다.
2. 중복 제거 후 실제 XLSX에 선택될 수 있는 공고 수가 200개 미만이면, 이미 구현된 보조 플랫폼을 점핏 → 캐치 → 인크루트 → 고용24 → 스타팅 순으로 조사한다.
3. 각 플랫폼 완료 뒤에는 원시 포함 건수가 아닌 `select_jobs_for_workbook(..., limit=200)`의 고유 공고 수를 다시 계산한다. 이 수가 200개가 되는 즉시 이후 보조 플랫폼 조사를 중지한다.
4. 기존 보조 플랫폼을 모두 마친 뒤에도 200개 미만인 경우, 공개 목록·상세 페이지에서 회사명, 제목, 경력, 근무지, 마감일, 업무를 확인할 수 있는 커리어(Career)를 추가 보조 출처로 조사한다.

## 품질과 한계

- 영구 조사 이력에 있는 URL은 상세 요청 전에 건너뛴다. 서로 다른 플랫폼에서 같은 회사·공고명이 발견되더라도 출력 선택 단계에서 하나만 남긴다.
- 5년 이상 필수, 리드·시니어 중심, 비백엔드 중심, 마감, 상세 접근 실패 공고는 포함하지 않는다.
- 200개는 강한 목표다. 모든 순차 출처를 확인한 뒤에도 고유하고 적합한 공고가 200개보다 적으면, 기준을 완화하거나 가짜 행을 추가하지 않고 확인된 수만 보낸다. 부족 원인은 `요약`과 실행 이력에 남긴다.
- 접근 차단, 로그인 전용, 자동 수집을 명시적으로 금지한 사이트는 자동 수집 출처에 넣지 않는다.

## 코드 변경 범위

- `scripts/collect_it_jobs.py`
  - `FALLBACK_MIN_INCLUDED`를 200개 목표 상수로 교체한다.
  - 보조 조사 중단 조건을 원시 `collected_jobs` 길이 대신 고유 선택 공고 수로 바꾼다.
  - Career 수집기와 상세 검증을 추가하고, 기존 보조 출처 뒤의 최종 확장 출처로 등록한다.
  - 수집 요약에 목표 대비 현재 고유 공고 수와 부족 사유를 적는다.
- `tests/test_collect_it_jobs.py`
  - 원시 중복이 200건 이상이어도 보조 출처가 계속 실행되는 테스트를 추가한다.
  - 기존 보조 출처 후에도 200개가 안 될 때 Career가 실행되는 테스트를 추가한다.
  - 고유 200개가 되면 이후 확장 출처를 호출하지 않는 테스트를 추가한다.

## 검증

1. 새 테스트가 기존 코드에서 실패하는지 확인한다.
2. 최소 구현 후 단위 테스트 전체와 Python 컴파일을 통과시킨다.
3. 실제 수집은 Telegram 없이 실행해 최종 XLSX의 3개 시트·8개 헤더·고유 공고 수를 검증한다.
4. 검증된 최종 파일만 Telegram으로 보낸다.
