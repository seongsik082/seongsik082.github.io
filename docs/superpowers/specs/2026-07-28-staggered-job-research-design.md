# 격일 대량 채용공고 조사 설계

## 목적

전국의 2년차 백엔드 연관 공고를 넓게 상세 확인하되, 한 번 상세 확인한 공고는 다음 실행에서 다시 열지 않는다. 사용자가 매일 같은 공고를 받지 않으면서도 신규 공고를 빠르게 축적하는 것이 목표다.

## 사용자 노출 결과

- 지역 필터는 적용하지 않는다. 전국 공고를 수집한다.
- `오늘 우선 확인 TOP 5`는 `요약` 시트, Telegram 메시지, 실행 기록에서 제거한다.
- `채용공고` 시트는 기존의 8개 열 구성을 유지하고 최대 100개 공고를 담는다.
- 적합한 신규 공고가 100개보다 적으면 확인된 만큼만 담는다.

## 격일 조사 일정

날짜의 일(day-of-month)을 기준으로 조사군을 고정한다. 실행이 빠지거나 재시작되어도 같은 날짜에는 같은 조사군을 사용한다.

| 날짜 | 상세 확인 대상 | 목표 |
| --- | --- | --- |
| 홀수일 | 사람인, 잡코리아 | 각 200건 |
| 짝수일 | 원티드, 랠릿 | 각 200건 |

랠릿은 첫 페이지에만 제한하지 않고 여러 페이지를 순회해 최대 200개의 백엔드 후보를 확보한다. 각 플랫폼에서 후보가 부족하면 가능한 후보만 상세 확인한다.

## 조사 이력

`/Users/kss/.codex/automations/it/researched-jobs.json`을 영구 이력으로 사용한다. 키는 추적 파라미터를 제거한 공고 URL이다.

- 상세 페이지를 정상 응답으로 열고 포함 또는 제외 판단을 마친 공고는 URL, 출처, 확인일, 판단 결과를 기록한다.
- 다음 수집에서는 상세 요청 전 이력 URL을 제외한다.
- 네트워크·상세 접근 실패 공고는 이력에 확정하지 않아 다음 실행에서 재시도한다.
- 이력으로 건너뛴 공고 수는 요약과 실행 기록에 남기되, `제외_검토` 시트에 수백 행을 반복해 쓰지 않는다.
- 이전의 “전날 XLSX와 중복이면 오늘·내일 마감만 재포함” 규칙은 이력 기반의 엄격한 재조사 제외로 교체한다.

## 처리 흐름

1. 날짜에 따라 해당 플랫폼 2개만 선택한다.
2. 두 플랫폼에서 최대 200개씩 후보 URL을 수집한다.
3. 영구 이력에 있는 URL을 제거한다.
4. 남은 URL의 상세 페이지를 열어 포함·제외 판단한다.
5. 정상적으로 판단된 URL을 이력에 기록한다.
6. 적합 공고를 우선순위 순으로 최대 100개 선정한다.
7. XLSX를 생성하고 검증한 뒤 Telegram으로 전송한다.

## 오류와 검증

- 상세 접근 실패는 `제외_검토` 시트에 남기고 다음 실행에서 재시도한다.
- XLSX 검증은 3개 시트, 8개 `채용공고` 헤더, 필터, 고정 행, 링크를 확인한다.
- Telegram 전송은 검증 성공 후에만 수행하며 기존 일일 전송 가드를 유지한다.
- 2026-07-28 샘플은 사용자 요청에 따라 `--force-send`로 전송한다.

## 테스트 범위

- 조사 이력의 기록, 사전 제외, 실패 공고 재시도
- TOP 5 제거와 최대 100개 선택
- 기존 XLSX 구조 및 Telegram 전송 전 검증 회귀
